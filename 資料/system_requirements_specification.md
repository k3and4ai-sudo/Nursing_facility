# 介護施設統合AIシステム「ケア・リンク (Care-Link)」
# 要求定義書 兼 要件仕様書 (System Requirements Specification: SRS)

---

## 第1部: 要求定義書 (Business & User Requirements)

### 1.1 システム開発の背景と目的
本システム「ケア・リンク (Care-Link)」は、Linux (Ubuntu) サーバーPCを中心とし、Androidスマホ・タブレットをクライアント端末とする介護施設統合AIシステムです。**ローカルAI（Ollama / Gemma）**、**スマートウォッチ**、および**Google連携・暗号化メール同期**を活用し、介護スタッフの負担軽減、利用者の安全・安心向上、および遠方のご家族との確実な情報共有を実現します。

### 1.2 クライアント端末とモード切り替えコンセプト
クライアント端末（Androidスマートフォン / タブレット）には統合アプリを導入します。
アプリ起動時に**ユーザーID**でログインすると、サーバーPCに事前登録されたユーザー区分を取得し、自動的に最適な動作モードへ表示・機能を切り替えます。

```text
                               ┌─> 【利用者モード】       (大文字・超シンプル操作・機能制限)
                               ├─> 【介護スタッフモード】 (統合ダッシュボード・バイタル・割り込み)
[ログイン (ユーザーID認証)] ──┼─> 【ご家族モード】       (グループ内通信限定・暗号化更新同期)
                               └─> 【訪問理容・美容師モード】(カット予約・姿勢注意点・施術報告)
```

### 1.3 グループ単位のセキュリティ境界
システム内では **「利用者 1名 - 担当介護スタッフ - ご家族」** を1つの限定グループとして構成します。
ご家族アカウントは**自身が所属するグループ内のみ**にアクセスが制限され、他の利用者のプライバシー情報や施設全体のデータへアクセスすることはできません。

### 2.2 認証と動的モード切り替え仕様

1. **ログイン処理**:
   * アプリ起動時、ユーザーIDおよびパスワード（またはピンコード/バイオメトリクス）を入力。
   * サーバーPCの `/api/auth/login` へ認証リクエストを送信。
2. **ユーザー区分レスポンス**:
   * サーバーは認証成功時、対象ユーザーの `role`（`patient`, `staff`, `family`, `barber`）および所属 `group_id` を返却。
3. **クライアントUIの動的切り替え**:
   * **`role == 'patient'`**: 利用者モードUIへ遷移。大きな文字（32px以上）、マイクボタンメインの機能制限画面。
   * **`role == 'staff'`**: スタッフモードUIへ遷移。全機能ダッシュボード、リアルタイムアラート、バイタルグラフ、インターホン。
   * **`role == 'family'`**: ご家族モードUIへ遷移。所属グループ内のみのデータ閲覧・チャット・面会予約。
   * **`role == 'barber'`**: 訪問理容・美容師モードUIへ遷移。予約一覧、カット・顔剃りメモ、施術後の申し送り報告。

### 2.3 ユーザー区分別 モード仕様

#### ① 利用者モード (Patient Mode)
* **超シンプルUI**: 画面上のボタン数を削減し、視認性の高い超大文字（32px以上）と高コントラストデザインを採用。
* **音声対話 & 自動バイタルパース**: マイクボタン1タップで発話。「体温36.5度」等の数値をWhisper+Gemmaが抽出・記録。
* **認知症傾聴プロンプト**: 否定・修正を行わない安心感重視のAI応答。
* **2秒自動応答インターホン (Pattern A)**: スタッフからの呼び出し時、2秒後に自動応答してハンズフリー通話を開始。
* **Googleカレンダーリマインド**: 服薬・予定時刻に音声で優しく案内。

#### ② 介護スタッフモード (Staff Mode)
* **統合ダッシュボード**: 緊急赤フラッシュアラート、リアルタイムバイタル一覧、1日の会話要約。
* **対話監視 & 割り込み (Pattern B)**: 利用者とAIの会話をリアルタイム監視し、スタッフのテキスト/音声を割り込み送信。
* **双方向インターホン (Pattern A)**: 各部屋の端末とのリアルタイム音声通話。
* **利用者マスター & グループ管理**: 利用者の登録、端末ID紐付け、ご家族アカウントのグループバインド。
* **申し送り & スタッフチャット (Pattern C)**: シフト引継ぎノートの記録とスタッフ間リアルタイムメッセージ。

#### ③ ご家族モード (Family Mode)
* **グループ内限定通信**: 紐付けられた利用者・担当スタッフのみとメッセージ・写真・動画の送受信。
* **リアルタイム様子・バイタル確認**: 本日の体温、食事量、AIとの会話の雰囲気（ご機嫌状態）の閲覧。
* **面会予約 (Google Calendar連動)**: 空き日時を確認して面会予約を送信。

#### ④ 訪問理容・美容師モード (Visiting Barber Mode)
* **理美容予約一覧**: 本日および今後のカット、顔剃り、カラー、パーマの予約リスト表示。
* **姿勢・認知症注意点の確認**: 「首を後ろに倒すのが困難」「洗髪時は声かけが必要」等の注意点閲覧。
* **施術完了報告**: 施術内容、ご本人のご機嫌、皮膚の状態などを記入し、スタッフおよびご家族へ共有。

### 2.4 グループ機能 ＆ 施設外メール送信・暗号化データ同期仕様

#### 1. グループ単位のアクセス制御
* データベース上で `groups` テーブルを定義。`group_id` にて「利用者ID - 担当スタッフIDs - ご家族IDs」をバインド。
* ご家族からのすべてのAPIリクエスト/WebSocket接続に対し、サーバー側で `group_id` を検証し、自グループ外のデータアクセスを厳格に遮断。

#### 2. 登録メールアドレスによる施設外メール送受信
* グループメンバー間で登録されたメールアドレス宛に、施設外からでもメールを送受信可能。
* サーバーPC内に **SMTP/IMAP メール同期エンジン** を搭載し、定期的にメール受信・自動レスポンス処理を実施。

#### 3. ご家族からの要求に応じた暗号化データ送信 & アプリ復号化
```text
【ご家族アプリ / メール】                 【Ubuntu サーバーPC】
       │                                        │
       │ ── (1) 更新要求 / メールリクエスト ──> │
       │                                        │ ── (2) 該当利用者の最新データ取得
       │                                        │ ── (3) クライアント固有鍵でデータを暗号化
       │ <── (4) 暗号化データパケット送信 ───── │    (AES-256-GCM / 密閉ペイロード)
       │
       ▼
(5) ご家族アプリ内で復号化
    -> アプリ画面（バイタル・写真・日誌）へ即座に反映
```

* **暗号化仕様**:
  * サーバーPCから施設外のご家族アプリ（またはメール）へデータを送信する際、平文の個人情報は送信せず、クライアント固有の暗号化キーを用いて **AES-256-GCM** でパケット全体を暗号化。
  * ご家族アプリ側で受信した暗号化パケットを復号化し、アプリ内の画面（バイタルグラフ、写真、日誌）へ安全に反映。

## 2.5 非機能要件 (Non-Functional Requirements)

1. **サーバー環境 (Ubuntu Linux)**:
   * Systemd サービス登録によるOS起動時のバックエンド自動立ち上げ。
   * GPU (NVIDIA RTX 2060以上) メモリ管理により、Gemma 26Bの高速推推を維持。
2. **クライアント環境 (Android)**:
   * Android 8.0 以上に対応したレスポンシブアプリ。
   * オフラインキャッシュ機能を備え、通信一時切断時も画面表示を保護。
3. **セキュリティと暗号化管理**:
   * SQLiteデータベース内は `Fernet` (AES-128) で暗号化保存。
   * 施設外通信・メール添付パケットは `AES-256-GCM` で暗号化し、不正傍受を完全に防止。
